# Retrospective old-Tamil-glyph audit — புதையல் scans 120 and 198–245

Date: 2026-08-30

## Why this audit was opened

During Part 006, high-resolution inspection showed that the edition's old/faint final `லை` glyph can look like a bare final `ல்` at ordinary zoom. The first Part-006 pass therefore falsely shortened source readings such as `தெரியவில்லை` to `தெரியவில்ல`.

Because earlier Pudhaiyal batches had used the same visual method, previous assistant-introduced corrections were re-opened wherever the same glyph risk existed. The native scan remains the controlling source; the user's transcription remains the comparison baseline.

## Result

Native high-resolution reinspection establishes **23 readable physical scans with earlier assistant `லை`-loss errors**:

- Part 003: **scan 120 / printed 118**;
- Part 005: **scans 198, 199, 201, 207, 214, 220, 221, 225, 228, 229, 230, 231, 233, 234, 235, 238, 239, 241, 242, 243, 244, 245**.

Canonical page records and assembled Tamil have been corrected accordingly.

## Explicit non-normalization checks

This audit does **not** establish a mechanical replacement rule. Each glyph cluster is judged from its own source pixels.

Source-supported forms that remain unchanged include, among others:

- scan 229: `தீண்ட வில்லையே`;
- scan 244: first `தெரியவில்லையே`;
- other old/colloquial forms where the final glyph is genuinely different or the word is otherwise source-supported.

Never replace every `வில்ல`/`இல்ல` occurrence globally.

## Damaged-source boundary

Scans **215–219 and 223–224** remain `needs-review` because repair/tape or physical loss hides source pixels. This retrospective audit does not infer missing letters from grammar, neighboring text, or the newly recognized typeform. The user baseline remains provenance-qualified where the native witness is absent.

## Permanent visual rule established by this audit

Before overriding a supplied baseline because a final letter or vowel sign appears absent:

1. enlarge the **complete glyph cluster**, not only the apparent terminal stroke;
2. explicitly consider historical/old Tamil typeforms and faint vowel marks, especially `ை` in `லை`;
3. compare the same typeform elsewhere in the same edition when useful;
4. inspect more than one scale/contrast if the mark is faint;
5. change the baseline only when native pixels positively establish a different reading;
6. if pixels remain genuinely ambiguous, retain the baseline with `needs-review` rather than manufacture an old/short form;
7. never apply a global normalization or de-normalization rule from one glyph discovery.
